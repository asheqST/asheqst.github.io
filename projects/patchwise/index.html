AI securityIndependent project · 2025

Patchwise

Abstract

An application-security assistant that finds vulnerabilities, explains them in standard terms, and suggests fixes that a developer reviews and approves.

Keywords

Application securityOWASPCWELLMs

The problem

Security review is a bottleneck. Findings arrive late, are written for specialists, and leave developers to work out the fix. AI coding assistants accelerate development, and they can accelerate the introduction of vulnerabilities just as easily.

Approach

Patchwise proposes analyzing code from a snippet, a repository, or a CI pipeline, and reporting each finding mapped to OWASP and CWE categories with a plain-language explanation, a suggested fix, and a test that demonstrates the issue is resolved.

Design principles

  • A human approves every change. Suggested fixes are proposals, never automatic edits.
  • A standard taxonomy. Mapping to OWASP and CWE makes findings comparable and reportable.
  • Explain, then fix. Developers learn the pattern, not just the patch.

Security considerations

  • AI patches can introduce new flaws. Every suggestion ships with a test and requires review before it is applied.
  • Customer code is the crown jewel. Each organization’s code and findings are isolated, and exposure to external models is minimized.
  • False confidence is a risk. Findings carry their evidence, so reviewers can challenge the tool rather than trust it.

Outlook

As more code is written with AI assistance, security review has to move at the same speed. Pairing automated findings with explainable, test-backed fixes keeps humans accountable while removing the bottleneck.

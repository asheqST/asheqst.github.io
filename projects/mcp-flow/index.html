MCP Flow

Overview

An experimental extension to the Model Context Protocol that lets AI tools run multi-step, stateful interactions while staying compatible with existing clients.

Technologies

Model Context ProtocolAI agentsTypeScript

Problem and motivation

Tools built on the Model Context Protocol (MCP) work as single request-and-response exchanges. Real workflows often need a dialogue: collecting missing information, validating input and retrying, or guiding a user through several steps.

Approach

MCP Flow adds interactive sessions that keep state across turns, with built-in patterns for guided wizards, validation with retries, and clarifying questions. Everything sits behind an opt-in experimental capability, and an evaluation harness exercises example servers and reports the results.

Technical design considerations

  • Backward compatibility first. Existing MCP clients and servers keep working unchanged.
  • Patterns, not just primitives. Common interaction shapes come ready to use, which keeps implementations consistent.
  • Measured behavior. Interactions are evaluated, not assumed to work.

Security considerations

  • State is attack surface. Sessions that persist across turns must be scoped, expired, and protected from hijacking.
  • Validate every turn. Each step’s input is checked before it advances the flow.
  • Opt-in by design. Nothing changes for clients that do not request the capability.

Outlook

As agents take on longer tasks, tools need to hold a conversation, not just answer a call. Doing that in a standard, compatible way avoids every vendor inventing its own incompatible version.

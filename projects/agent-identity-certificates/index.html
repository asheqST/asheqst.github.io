Agent Identity Certificates

Overview

Verifiable identity for AI agents, so every action an agent takes can be attributed, scoped, and audited, including across organizations.

Technologies

Agent identityPKIMCPZero Trust

Problem and motivation

AI agents increasingly act on behalf of people and organizations, calling tools, services, and other agents. Today’s access controls identify the user behind an agent, not the agent itself. That makes it hard to limit what a specific agent may do, to audit what it did, or to trust an agent that belongs to another organization.

Approach

Each agent receives its own certificate-based identity that states who it is and what it is permitted to do. A gateway in front of tools and services verifies that identity on every request, enforces its scope, and records the outcome. Short-lived, request-bound credentials reduce the value of stolen tokens, and a trust registry lets organizations recognize each other’s agents without sharing secrets.

Technical design considerations

  • Identity per agent, not per user. Permissions and audit trails follow the specific agent.
  • Proof on every request. Each call demonstrates possession of the agent’s credential.
  • Federation by design. Trust across organizations is a core capability, not an afterthought.

Security considerations

  • Compromise is contained. A misbehaving agent can be revoked without disrupting other agents acting for the same user.
  • Replay and theft are limited. Short lifetimes and request binding make intercepted credentials of little use.
  • Accountability survives disputes. Every decision is recorded against a verifiable identity.

Outlook

Agents will soon transact across organizational boundaries the way web services do today. Just as TLS made it possible to trust a website, a verifiable identity layer is what will make it possible to trust an agent, and it is the natural control point for policy, audit, and liability.

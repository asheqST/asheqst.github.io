Agentry

Overview

An operating layer for AI agents that gives them what processes get from an operating system: isolation, scheduling, resource limits, and controlled communication.

Technologies

AI agentsMCPSandboxing

Problem and motivation

Agents are moving from calling predefined tools to writing and running their own code. Without the controls an operating system provides, one agent can consume unbounded resources, interfere with other agents, or reach capabilities it was never meant to have.

Approach

Agentry treats each agent as a process. Agents run in isolated runtimes with explicit resource limits, are scheduled under configurable fairness policies, communicate through a mediated message bus, and reach external capabilities only through registered MCP servers. Every action emits an event, so behavior can be observed and audited.

Technical design considerations

  • Least privilege per agent. Capabilities are granted explicitly, never inherited.
  • Fair sharing. Scheduling policies prevent any single agent from starving the others.
  • Observable by default. Lifecycle, scheduling, and messaging events are recorded for monitoring.

Security considerations

  • Isolation is the security boundary. The sandbox that runs agent-written code is the most critical component, and it must be a hardened, maintained one.
  • Mediated communication. Agents cannot reach each other directly, so messages can be inspected and rate-limited.
  • Capabilities through a registry. External tools are reachable only through approved MCP servers.

Outlook

Operating systems made multi-user computing safe by giving every program a boundary. Agentic computing needs the same idea, and the organizations that adopt it early will be able to run many agents without trusting any one of them completely.
